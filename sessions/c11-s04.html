Chapter 3: the shell as a place you can move around in

Every command has the same shape, command options arguments. The shell always sits in a working directory; pwd prints it, cd changes it, and a bare cd goes home. The root / contains everything, ~ is home, .. the parent. Absolute paths start from the root, relative paths from where you are.

Then the everyday tools: mkdir and touch to create, ls -l to inspect (a leading d is a directory), wc for lines, words and characters, cat, less, head and tail to read. > overwrites a file and >> appends, and the chapter's recurring warning is that there is no undo: rm deletes for good, and folders need -r for both cp and rm.

Chapter 4: small tools, chained

The heaviest part of this chapter, Search, is the part to skip. grep, regular expressions and find live there, and the announcement takes them out of the reading: R4DS chapter 15 covers the same syntax in a later session. What remains is the help pages, man and apropos; the wildcard *; history and aliases in ~/.bash_profile; and diff, sdiff and the content hashes md5 and shasum.

The pipe | turns one program's output into the next one's input: ls *.jpg | wc -l counts the JPEG files in a directory. The chapter closes on make: rules made of a target, its dependencies and Tab-indented commands, which run only when the target is missing or a dependency has changed. That is the same idea as last week's lecture, from the shell side.

Chapter 5 is not in the reading

Bash as a programming language, arithmetic, variables, exit status, if, arrays, functions and PATH, is the chapter the syllabus's "shell scripting" pointed at, and the announcement leaves it out. Nothing from it can be on the quiz. It is still worth a read once the quiz is done, because Thursday's lecture and the later scraping sessions build on it.

What you should be able to do afterwards

  • Open a terminal from RStudio and move around the file system without a file browser
  • Create, copy, move, rename and delete files and folders, knowing what cannot be undone
  • Filter and count lines with grep, a regular expression and a pipe
  • Send output to a file with > or >>, and know which one you need
  • Write a short .sh script with a shebang, make it executable and run it
  • Run an R script from the shell with Rscript, passing it arguments
  • Explain where the shell fits in a reproducible pipeline, next to Make and cron
