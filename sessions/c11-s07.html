R4DS 19: keys, and which join keeps what

Every join pairs a primary key, which identifies each row of its own table, with a foreign key that points to it from another. In the flights data, a plane's tail number is the primary key of planes and a foreign key in flights; the weather table needs two variables together, place and hour. The one trap in that data is year: flight year in one table, build year in the other. Join without naming the key and dplyr uses every shared name, both of them, and most planes find no match.

left_join() keeps every row of the first table and is the one to reach for; right, full and inner keep the second table, both, or only matches. Filtering joins keep or drop rows by whether they match, without adding columns: anti_join() is how to find what is missing. A row that matches twice appears twice, and keys duplicated on both sides multiply rows, which dplyr flags with a warning.

R4DS 20 and 21: spreadsheets, then databases

Spreadsheets are read with read_excel() by trial and error: name the columns (and skip the old header), say which strings mean missing, choose types, pick a worksheet or a cell range. Excel stores no integers and keeps dates as day counts, and a round trip through Excel loses column types.

For databases, DBI connects and runs SQL, and dbplyr translates ordinary dplyr code into SQL. A database table in R is lazy: nothing runs until you collect(), and show_query() shows the SQL. Written order is SELECT, FROM, WHERE, GROUP BY, ORDER BY; evaluation runs FROM, WHERE, GROUP BY, SELECT, ORDER BY, which is why a filter on a summary becomes HAVING. SQL compares with a single =, quotes strings with single quotes, and drops missing values silently when summarising.

What you should be able to do afterwards

  • Explain why data is split into related tables, and what normalization buys
  • Name the primary and foreign keys in a set of tables, and check a key is unique
  • Choose the right join and predict how many rows it returns
  • Specify join keys explicitly and handle clashing column names
  • Read a basic SQL query and map each clause onto a dplyr verb
  • Query a database from R with dplyr, see the SQL, and collect the result
