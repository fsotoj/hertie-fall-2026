R4DS 24: scraping with rvest, and whether you may

The chapter starts with the law, not the code. Scraping is likely to be fine when the data are public, non-personal and factual. Terms of service bind a US visitor only after an explicit action such as creating an account, but European courts have enforced them without one. Personal data is the real danger: the 2016 release of 70,000 scraped dating profiles is the cautionary case. Facts are not protected by US copyright, although Europe adds a separate right over databases. Wait between requests, and use an API where one exists, because it gives more reliable data.

Then the mechanics. read_html() parses a page; CSS selectors find elements (p, .class, #id). The distinction that matters is html_elements() against html_element(): the first returns every match, the second exactly one result per input, with a missing value where nothing matches, which keeps rows aligned when some items lack a field. html_text2() extracts text as a browser would show it, html_attr() extracts attributes (always as strings), and html_table() turns HTML tables into tibbles. rvest runs no JavaScript, so a page built in the browser needs a real one behind it.

APIs for Social Scientists: the ground rules

A collaborative review of APIs useful in social science, each chapter answering the same questions: what the API provides and who runs it, how to get access, what a simple call looks like, how to reach it from R, and which research has used it.

The best-practice chapter has three rules. Read the developer agreement, even when a package does the calls for you, because it says what you may do with the data; Cambridge Analytica is its example of API data abused by a researcher. Never put a key in your code: it leaks when the code is shared and stays in your command history. Store it in your user-level .Renviron as NAME=value, restart R, and read it with Sys.getenv(). And cache your calls with memoise, so an identical request is answered locally instead of spending the rate limit again.

What you should be able to do afterwards

  • Scrape a static page with rvest: parse, locate with XPath or CSS, extract, tidy
  • Use html_elements() for rows and html_element() for columns, so missing fields stay aligned
  • Read an HTML table into a tibble and fix its types
  • Scrape politely: robots.txt, pauses, local copies, an identifiable user agent
  • Call a web API from R and turn its JSON response into a data frame
  • Keep API keys out of your code
