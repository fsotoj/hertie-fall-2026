R4DS 12 to 16: the vector types, with regular expressions at the centre

The first chapters are about small exact rules that are easy to get wrong. A missing value is contagious: NA == NA is NA, so filter(x == NA) keeps nothing and is.na() is the tool. month == 11 | 12 selects every row, because the 12 is read as TRUE; %in% avoids the trap. case_when() takes the first condition that matches. round(2.5) is 2, because R rounds halves to the even number. str_c() keeps a missing value missing, while str_glue() writes the letters "NA". factor() silently turns a value outside its levels into NA; fct() refuses.

Chapter 15 is the one the syllabus flags. A regular expression is a compact language for patterns: . any character, ?, + and * for how many, [abc] and [^abc] for sets, ^ and $ for the start and end. In R every backslash is written twice, so a literal dot is "\\.". Matches never overlap, alternation binds loosely (so ^a|b$ means "starts with a, or ends with b"), and parentheses both group and capture. The chapter ends with advice worth more than any single rule: test a pattern against examples that should and should not match.

ADCR: how a web page is built, and how to point at a piece of it

Automated Data Collection with R (2015) is the instructor's own book, and these chapters are the groundwork for scraping. HTML is a tree of elements, each with a start tag, content and an end tag, and attributes such as href in the start tag. XML follows the same shape under stricter rules: one root, every element closed, properly nested. JSON is lighter, built from objects in braces and arrays in brackets, and R turns an array of mixed types into a vector of the most general one.

XPath is how you point at nodes. /html/body/div is a full path from the root; //p/i finds italics inside paragraphs anywhere. One slash means a direct child and two mean any descendant, so on the book's example page //div/i finds nothing and //div//i finds both quotes. Predicates in brackets filter: [1], [last()], [@date='June/2003'], [contains(text(), 'magic')].

Chapter 8 teaches the same regular expressions as R4DS 15 in a different dialect, mostly POSIX classes such as [[:alpha:]], on a jumbled Simpsons phone book and one example sentence. Two of its points are traps: a POSIX class needs double brackets, and .+ is greedy while .+? stops at the first match. The book's code uses the older XML package; the ideas carry over to rvest, the function names do not.
